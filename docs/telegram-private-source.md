# ربط قناة اليمن نت الخاصة بناشر الجنوب فويس

تضيف هذه الإضافة منشورات القناة الخاصة إلى مسار الجنوب فويس الموجود: كشف التكرار، إعادة صياغة النص الخام، ثم النشر في قسم **أخبار وتقارير**. لا تغيّر هذه الإضافة مستودع `alymenet-telegram-publisher` ولا تلغي إرسال ذلك البوت الحالي إلى قناة تيليجرام.

## قبل التفعيل

1. أنشئ بوت استقبال منفصلًا عبر `@BotFather`. لا تستخدم توكن بوت النشر الصادر في `TELEGRAM_BOT_TOKEN`؛ يجب أن يبقى بوت المصدر منفصلًا عن أي بوت آخر.
2. أضف بوت الاستقبال إلى القناة الخاصة **كمشرف** حتى تصله تحديثات `channel_post`. لا يلزم منحه صلاحية نشر رسائل.
3. انشر رسالة اختبار جديدة في القناة بعد إضافة البوت، ثم استخرج رقم القناة بالطريقة أدناه.
4. في مستودع `janoub-auto-publisher` أضف من **Settings → Secrets and variables → Actions**:
   - Secret `TELEGRAM_SOURCE_BOT_TOKEN`: توكن بوت الاستقبال الجديد.
   - Variable `TELEGRAM_SOURCE_CHAT_ID`: رقم القناة، ويكون عادةً بصيغة سالبة مثل `-1001234567890`.
5. نفّذ ترحيل قاعدة البيانات مرة واحدة في Supabase SQL Editor: `migration/20260925_telegram_source_cursor.sql`.
6. شغّل GitHub Action بالطريقة المعتادة. يبدأ الاستقبال في كل مرة يعمل فيها تشغيل ناشر الجنوب فويس؛ لا تنشئ جدولة إضافية لهذا التكامل.

## معرفة رقم القناة دون طباعة التوكن

على جهاز موثوق مع تثبيت `requests`، اضبط `TELEGRAM_SOURCE_BOT_TOKEN` في متغير البيئة، ثم شغّل:

```bash
python scripts/show_telegram_chat_id.py
```

يعرض السكربت أرقام معرفات القنوات فقط، ولا يطبع التوكن أو نص المنشور. إذا لم يظهر رقم القناة، تأكد من إضافة البوت كمشرف، ثم أرسل منشورًا جديدًا في القناة وأعد التشغيل. يحتفظ Telegram بالتحديثات الواردة فترة محدودة؛ بعد ضبط GitHub Variable شغّل الناشر لالتقاط التحديثات المعلقة.

## سلوك المعالجة

- يُقبل فقط تحديث `channel_post` الوارد من معرّف القناة المحدد.
- يُستخدم نص الرسالة أو الوصف النصي للصورة كمادة خام. عنوان الخبر هو أول سطر غير فارغ، ويُمرر النص الكامل إلى دالة إعادة الصياغة الموجودة.
- يُسند القسم دائمًا إلى **أخبار وتقارير**.
- رابط المصدر يكون رابط منشور القناة؛ ويُستخدم مفتاحًا ثابتًا لمنع إدخاله مرتين في `posts`، مع تخزين مؤشر Telegram في `bot_source_cursors`.
- قبل كل polling يفحص الناشر حالة webhook لبوت المصدر. إذا كان مفعّلًا، يزيله عبر `deleteWebhook` مع `drop_pending_updates=false`، ويتحقق من تعطيله قبل قراءة التحديثات؛ تبقى التحديثات المعلقة في Telegram. لا تستخدم توكن بوت المصدر في مستهلك polling آخر بالتزامن، وإلا سيستمر خطأ `409`.
- منشورات قناة Telegram لا تمر على `apply_full_extraction` الخاص بصفحات RSS؛ نص المنشور نفسه هو النص الكامل المتاح.
- إذا احتوى المنشور على صورة، تُنزّل أكبر نسخة متاحة عبر `getFile`، ثم تمر عبر فحص الشعارات المحظورة ومعالجة/ضغط الصور وتصميم العنوان والرفع إلى Supabase Storage، مثل بقية صور الأخبار. لا يتضمن هذا التغيير نقل الفيديو.
- يحد Telegram Bot API الرسمي تنزيل الملف عبر `getFile` بـ20MB؛ إذا تجاوزت الصورة هذا الحد يُنشر النص دونها. أما أخطاء الشبكة العابرة فتؤجل نشر الخبر لإعادة المحاولة. [Telegram Bot API: File](https://core.telegram.org/bots/api#file)
- إذا فشل نشر خبر من الدفعة، لا يتقدم المؤشر للدفعة، ليعاد جلبها في التشغيل التالي؛ يمنع `source_url` تكرار الأخبار التي سبق نشرها بنجاح.
- إذا لم تُضبط متغيرات بوت المصدر، يعمل النظام كما كان: فيدات RSS لا تتغير ولا يتوقف الناشر.

## حدود الوصول

الرابط الخاص بالدعوة `https://t.me/+...` لا يكفي وحده لقراءة القناة. يجب إضافة بوت الاستقبال نفسه إلى القناة. لا ترسل توكن البوت في المحادثات أو Issues أو سجلات Actions.
